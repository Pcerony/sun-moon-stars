# NFC 流程精简、抵达仪式与寻星罗盘设计

## 目标

本轮在现有视觉系统和 NFC 仪式基础上完成四项改进：

- 把“首次伙伴配对”和“抵达任务地点”做成叙事明确不同的两套月亮 NFC 动效。
- 删除不产生新信息的确认步骤，让每次主动操作都对应真实行为。
- 把探测器升级为以太阳为中心的寻星罗盘，并在接近目标时自动进入可扫描状态。
- 在所有具有角色含义的位置使用正式太阳、月亮、星星插图，并强化“太阳是手机使用者”的身份。

纸质地图仍由月亮负责整体导航。手机只提示当前区域、任务和近距离寻星反馈，不提供路线、距离或转向导航。

## 最终流程

```text
欢迎页“开始”
  -> 立即启动月亮 NFC 扫描
  -> 首次伙伴配对仪式
  -> 月亮介绍页“准备好了”
  -> 首页
  -> 选择附近任务
  -> 纸质地图提示页
  -> 主动扫描月亮项链
  -> 抵达任务地点仪式
  -> 任务页“开始探测”
  -> 寻星罗盘自动工作
  -> 接近目标后出现“扫描星星徽章”
  -> 主动扫描星星 NFC
  -> 共同收藏仪式
  -> 自动返回首页并更新积分
```

“准备好了”是唯一保留的非 NFC 确认按钮。它确认两位参与者已经完成线下自我介绍，不是单纯的页面跳转。

星空页继续通过底部 Dock 打开和离开，不再显示“继续探索”按钮。备用地图仍可从 Dock 打开，但不加入主任务流程。

## 三套 NFC 仪式

### 首次伙伴配对

首次扫描月亮项链时播放。太阳和月亮从两侧靠近，组成伙伴贴纸，然后进入月亮介绍页。只表达“成为伙伴”，不出现任务地点或星星。

### 抵达任务地点

每次到达纸质地图指向的大致区域后，太阳主动扫描月亮项链。该仪式不复用伙伴贴纸：

1. 月亮在上方作为柔和的地点信标出现。
2. 太阳从下方靠近信标。
3. 两者相遇后产生一圈地图式波纹。
4. 当前区域印章和任务贴纸依次显现。
5. 仪式结束后自动进入任务页。

这个画面表达“我们一起到达了任务区域”，不表达配对，也不绘制路线。

### 共同收藏星星

沿用已经确认的收藏仪式：太阳和月亮共同接住星星，并把它送入占据屏幕上半区的共同星空。结束后直接返回首页，积分和已收集星星同步更新，不再经过单独完成页。

## 寻星罗盘 A

### 视觉与交互

- 正式太阳插图固定在罗盘中心，代表持手机的年轻参与者。
- 正式星星插图位于目标方向，并随手机朝向沿罗盘外圈改变相对位置。
- 手绘圆环、波纹和少量“山”字形草纹构成探测场，不使用尖锐箭头或技术仪表盘造型。
- 接近目标时，圆环亮度、星星尺寸、震动和提示音逐渐增强。
- 页面进入时即请求方向权限并开始探测，不再显示“开始感应”。
- 信号连续达到接近阈值后，自动显示唯一的下一步按钮“扫描星星徽章”。
- 删除“找到了”和返回任务页的中间步骤。

探测器只提供近距离方向感和强弱反馈。目标方向在原型中仍是模拟值，不显示米数、路径或地图导航。

### 设备降级

- 不支持方向传感器或权限被拒绝时，保留静态罗盘和简短状态提示。
- 隐藏测试模式继续提供模拟强度的方法，普通参与者看不到。
- 无震动或 Web Audio 时，视觉反馈仍完整可用。
- 开启 `prefers-reduced-motion` 时，使用淡入、亮度变化和静态成功状态，不播放旋转、弹跳或飞行动画。

## 正式素材规则

角色含义必须使用以下透明 PNG：

- 太阳：`assets/ritual/sun.png`
- 月亮：`assets/ritual/moon.png`
- 星星：`assets/ritual/star.png`
- 品牌 Logo：`assets/branding/logo.png`

具体分配：

- 太阳用于首页身份标记、寻星罗盘中心和两类合作仪式。
- 月亮用于首次扫描、纸质地图提示、抵达仪式和合作仪式。
- 星星用于 Dock 星空入口、积分、任务奖励、寻星目标、收藏结果和队伍星空。
- Logo 只用于欢迎页、页头、首页 Dock 和 favicon，不作为太阳角色的替代品。
- 纯装饰的微小闪光可以继续使用通用图标，但任何代表任务奖励、参与者或可交互目标的图形都必须使用正式插图。

素材替换不能增加说明文字。无障碍名称通过 `aria-label` 或现有短标签提供。

## 状态与代码边界

- `src/state.js` 负责流程页面、任务完成、积分和收藏结果。星星成功后直接把页面设为 `home`。
- `src/ritual.js` 保留 `pair`、`moon`、`star` 三种仪式类型；其中 `moon` 明确定义为抵达仪式，不再表示第二次配对。
- `src/app.js` 负责扫描触发、仪式选择、探测器运行时状态和页面渲染。
- 逐帧角度、信号强度、接近计时器和动画阶段不写入持久工作流状态。
- `src/nfc.js` 继续只负责 Web NFC 能力与读取，不加入页面逻辑。

所有 NFC 扫描仍由用户点击直接发起，以满足 Web NFC 的用户手势要求。欢迎页“开始”应在同一次点击中切换到扫描状态并调用 NFC；读取失败时停留在配对页，显示必要的重试入口。

## 错误与中断

- NFC 不可用、读取失败或权限被拒绝时，不播放成功仪式，也不提前改变流程、积分或收藏状态。
- 首次扫描失败后显示重试；任务地点和星星扫描失败后恢复原扫描按钮。
- 离开探测页时立即移除方向监听、计时器、震动和音频。
- 信号必须连续达到阈值后才显示星星扫描入口，避免传感器抖动造成闪烁。
- 仪式播放期间锁定重复扫描；动画结束后只提交一次状态变化。

## 文案与视觉约束

- 继续遵守少文字、图标优先的原则，不增加说明卡片。
- 所有角色图保持手绘素材比例，不裁成通用圆形头像。
- 新抵达仪式和罗盘不能遮挡底部 Dock，也不能在 320 像素宽屏幕上贴边。
- 现有蓝色信息区、米色草纹交互区、青绿色 Dock 和圆角图片容器保持不变。
- 交互按钮只保留“开始”“准备好了”“扫描月亮项链”“开始探测”“扫描星星徽章”等真实动作。

## 测试与验收

自动测试覆盖：

- 首次配对成功前不提前写入月亮资料。
- 抵达扫描成功前不激活任务。
- 星星扫描只完成一次任务，增加一次积分，并直接返回首页。
- 没有活动任务时不能完成收藏。
- 三种仪式的阶段、时长和减少动态效果行为。

浏览器验收覆盖：

- 从欢迎页开始的完整隐藏模拟流程没有多余确认页。
- 首次配对、抵达和收藏三套动效的叙事与素材互不混淆。
- 罗盘进入后自动工作，达到阈值后稳定出现星星 NFC 按钮。
- 320 × 700、390 × 844、460 × 900 视口均无遮挡、贴边或文字溢出。
- 普通模式看不到模拟按钮，长按标题后仍能完成测试。
- 返回首页或切换页面后探测反馈全部停止。
- `prefers-reduced-motion` 下流程仍然清楚。

桌面浏览器只能验证模拟扫描、状态和视觉。真实 Web NFC 必须在 HTTPS、支持 NFC 的 Android Chrome 和实体标签上另行验收，未实测前不能声称硬件通过。
